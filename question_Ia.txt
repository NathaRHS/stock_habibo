## 1. Le contexte général

Le groupe **Habibo** possède plusieurs sociétés, par exemple :

* **HH** : produits d’hygiène, couches, etc.
* **HB** : produits alimentaires.
* **HM** : autre activité que tu ne m’as pas encore précisée.

Ces sociétés fabriquent ou gèrent leurs propres produits, puis les produits terminés arrivent dans un ou plusieurs entrepôts.

Ton application est donc un **WMS, Warehouse Management System**, qui doit gérer ce qui se passe entre :

**Produit fabriqué → réception → contrôle → rangement → stock → inventaire → préparation de sortie → livraison**

Et il y a deux applications qui travaillent ensemble :

**Web / Desktop**
→ utilisé surtout par les responsables.

**Application mobile Flutter**
→ utilisée surtout par les opérateurs dans l’entrepôt.

C’est une architecture qui me paraît très importante pour comprendre le projet :

```text
                    WMS
                     │
          ┌──────────┴──────────┐
          │                     │
      WEB / DESKTOP         MOBILE FLUTTER
          │                     │
     Responsable             Opérateur
          │                     │
  ouvre les sessions       scanne physiquement
  valide / contrôle        les marchandises
  choisit emplacement      saisit les quantités
  reçoit alertes           exécute les tâches
  génère rapports
```

# 2. Le concept central : la SESSION

C’est probablement **l’un des objets les plus importants de ton système**.

Je comprends qu’on ne peut pas simplement modifier le stock comme ça.

On doit passer par une opération contrôlée appelée **session**.

Il y aurait au minimum trois types :

```text
Session
│
├── Session d'entrée
├── Session d'inventaire
└── Session de sortie
```

Une session pourrait avoir notamment :

```text
- identifiant
- type
- société concernée
- document associé
- opérateur
- responsable
- date d'ouverture
- date de fermeture
- statut
- articles concernés
```

Et tu m’as donné trois statuts :

```text

EN_ATTENTE
VALIDE
```

⚠️ Mais leur signification exacte doit être clarifiée, parce que dans ton explication il y a quelques moments où je ne sais pas encore précisément quand on passe de l’un à l’autre.

# 3. Processus d'ENTRÉE 📥

Voilà comment je comprends le scénario.

Une société du groupe fabrique des produits.

Ils doivent entrer dans l’entrepôt.

Il existe alors un **bon de réception** contenant quelque chose du genre :

```text
BON DE RÉCEPTION BR-2026-00125

Article             Quantité prévue
------------------------------------
Couche bébé M          500
Savon 200g             300
Gel douche             150
```

Une personne **A**, opérateur dans l’entrepôt, reçoit ce document.

Elle demande ensuite à une personne **B**, responsable utilisant le Web/Desktop, d’ouvrir une **session d’entrée** correspondant à ce bon.

Le responsable B crée donc quelque chose comme :

```text
SESSION ENTREE #ENT-00042

Bon réception : BR-2026-00125
Société : HH
Statut : EN COURS

Articles attendus :
Couche bébé M     500
Savon             300
Gel douche        150
```

# 5. Le rangement dans l'entrepôt 🏗️

Et ici ton projet devient beaucoup plus intéressant qu'un simple :

```text
Article
emplacement = "A12"
```

Ton entrepôt possède une structure physique.

D’après ce que tu m’as expliqué :

```text
ENTREPÔT
   │
   └── RACK
        │
        └── EMPLACEMENT
                 │
                 └── ÉTAGE
```

Par exemple :

```text
Rack 01
│
├── Emplacement 01
│     ├── Étage 1
│     ├── Étage 2
│     └── Étage 3
│
├── Emplacement 02
│     ├── Étage 1
│     ├── Étage 2
│     └── Étage 3
│
└── Emplacement 03
```

Donc une adresse physique pourrait être :

```text
R01-E02-N02
```

qui voudrait dire :

```text
Rack 1
Emplacement 2
Niveau/Étage 2
```

Et ton exemple :

> Article1 → Rack1 → Emplacement2 → 2e étage

correspondrait donc à cette logique.

Le Web/Desktop voit les emplacements disponibles puis indique à l'opérateur :

```text
Couche bébé M
Quantité : 500

📍 Ranger dans :
Rack 1
Emplacement 2
Étage 2
```

L’opérateur va physiquement déposer la marchandise là-bas.

# 6. INVENTAIRE 🔎

À un autre moment, une personne **C** doit contrôler l’entrepôt.

Elle demande au responsable Web d’ouvrir une :

**session d’inventaire**

Le responsable crée la session.

C utilise ensuite le mobile pour recompter physiquement les marchandises.

Le principe serait :

```text
Stock théorique WMS
        VS
Stock réel compté
```

Par exemple :

```text
Article : Savon 200g

WMS :     300
Réel :    297

Écart :    -3
```

Le système détecte donc une anomalie.

Et le responsable Web reçoit une alerte :

```text
⚠ Écart d'inventaire

Savon 200g
Stock théorique : 300
Stock compté : 297
Écart : -3
```

Une fois l'inventaire terminé, le responsable peut générer un **rapport PDF** contenant probablement :

```text
Rapport inventaire

Date
Opérateur
Entrepôt
Société
Articles contrôlés
Quantité théorique
Quantité réelle
Écarts
Commentaires
etc.
```

# 7. SORTIE 📤

Maintenant Habibo reçoit une commande d'un client.

Il existe un **bon de commande** :

```text
Commande BC-2051

Couche bébé M      100
Savon               50
Gel douche          20
```

Une **session de sortie** est créée.

Quelqu’un vérifie d'abord si les produits sont disponibles.

Le système pourrait afficher :

```text
Couche bébé M

Demandé : 100
Disponible : 500

✓ Stock suffisant

Emplacement :
Rack 1
Emplacement 2
Étage 2
```

L’opérateur va ensuite physiquement récupérer les produits.

Il les scanne.

```text
100 / 100 Couche bébé M ✓
50 / 50 Savon ✓
20 / 20 Gel douche ✓
```

Puis il ferme la session de sortie.

Mais ici il y a une règle métier **très importante** que j'ai bien notée :

> Le stock n'est pas définitivement décrémenté immédiatement.

La commande est préparée, mais le produit n'est retiré du stock qu'après une **confirmation liée au bon de livraison / client**.

Donc il existe potentiellement une distinction entre :

```text
STOCK PHYSIQUE
STOCK DISPONIBLE
STOCK RÉSERVÉ
```

Et ça peut devenir extrêmement important pour ton modèle.

Imagine :

```text
Stock physique :   500
Réservé :          100
Disponible :       400
```

Même si les 100 unités ne sont pas encore définitivement sorties, **une autre commande ne devrait probablement pas pouvoir les réserver**.

C'est une des choses que je veux absolument clarifier avec toi.
